🛵 SidecarComments Plugin                                  *sidecar-comments*

A Neovim client for the `sidecar` CLI, which keeps review threads for any
UTF-8 text file in a `.comments` file beside it (`post.md.comments`,
`main.rs.comments`, ...). The source file is never modified.

The CLI owns the file format, IDs, ordering, source tracking, locking and
revisions. The plugin never parses or writes `.comments` text itself; it shows
threads in the source buffer, reports where they moved when you save, and
calls the CLI from keymaps.

REQUIREMENTS                                *sidecar-comments-requirements*

The `sidecar` CLI (format and protocol version 2) on `PATH`:
>
    brew install trogers1/tap/sidecar
<
Sidecars written by the old Lua-only version of this plugin
(`[@id 12-15 | base64]` headers) are not readable by the CLI and are reported
as errors.

USAGE                                           *sidecar-comments-usage*

In any file buffer:

<leader>sa          Add a thread on the current line
<leader>sa (visual) Add a thread on the selection. Charwise selections
                    become exact ranges; a linewise selection of one line is
                    a line thread, of several lines a range.
<leader>sv          Open the comments file at the thread under the cursor
<leader>so          Open the comments file

Adding a thread saves the source buffer first (the CLI records the commented
text from the saved file), creates the thread with the placeholder body
`comment`, opens the comments file and puts you in insert mode on that body.
Type the comment and save.

In a `.comments` file:

<CR>                Jump to the thread's location in the source
<leader>sr          Reply to the thread under the cursor (same placeholder
                    flow as adding)

EDITING BY HAND                                 *sidecar-comments-editing*

The comments file is meant to be edited directly. You can:

- change the text of any message (a message body may not be empty),
- delete a whole thread (this is how a thread is resolved): delete from its
  `[@th_<id> ...]` line through its `[/@th_<id>]` line, plus one blank line
  next to it, so exactly one blank line still separates the remaining
  threads. To delete the last remaining thread, empty the file entirely,
  including the `<!-- sidecar-format: 2 -->` line,
- add a reply by hand: a blank line, a `---user` line, then the text,
  placed before the thread's closing `[/@th_<id>]` line.

On save, the plugin runs `sidecar fix --add-missing-message-ids`, which gives
hand-written messages their IDs and metadata, and reloads the buffer.

Do not edit the `[@th_...]` header, the `<!-- sidecar-tracking: ... -->` line
or `<!-- sidecar-meta: ... -->` comments; add new threads with <leader>sa. If
the CLI rejects the saved file (for example a missing or extra blank line, or
an empty message), an error diagnostic shows the reason; fix the file and save
again, or run `:!sidecar validate --file %`.

FILE FORMAT                                     *sidecar-comments-format*

See `sidecar --help` and the CLI's format reference. A thread looks like:
>
    <!-- sidecar-format: 2 -->
    [@th_<thread-uuid> range:20:8-20:19]
    <!-- sidecar-tracking: {"tracking":{...}} -->
    ---user <!-- sidecar-meta: {"id":"<message-uuid>"} -->
    Can this failure be handled?

    ---bot <!-- sidecar-meta: {"id":"<message-uuid>"} -->
    Yes. I updated the error path so that ...
    [/@th_<thread-uuid>]
<
Locations are `file`, `line:N`, `range:L:C-L:C` (1-based UTF-8 byte columns,
end exclusive), `lost`, or `unresolved`. `---user` messages are from people,
`---bot` messages from agents.

TRACKING SOURCE EDITS                           *sidecar-comments-tracking*

Line and range threads follow your edits through extmarks. When you save the
source, the plugin sends their new positions to `sidecar editor-update`. A
thread whose text you deleted becomes `unresolved`: it keeps its
conversation, loses its highlight, and gets a warning diagnostic in the
comments file. Move it back with `sidecar thread move`, or let
`sidecar sync` find its text again. A line thread follows its line: rewriting
the line's text (`cc`, `S`) keeps it; deleting the line makes it
`unresolved`.

Positions are only sent when the buffer is written to its own file, and the
CLI rejects them if the saved file differs from the buffer (for example when a
formatter rewrote it after the write).

A thread is only highlighted when its stored coordinates were captured from
exactly the text in the buffer. Threads stored against other text (the file
changed outside Neovim, or another writer added or moved a thread while the
buffer has unsaved edits) are left unhighlighted with a warning. On the next
save the plugin runs `sidecar sync`, which re-matches them by their text, or
marks them unresolved if they cannot be found.

If the comments buffer has unsaved edits when you save the source, positions
are not sent until you save the comments file and then save the source again,
and you are warned.

OTHER WRITERS                                   *sidecar-comments-writers*

Agents and other tools should change threads through the CLI
(`sidecar message add --author-kind agent ...`), which locks the file. When
Neovim regains focus the plugin rereads every sidecar and reloads unmodified
comments buffers that changed on disk; comments buffers with unsaved edits are
left alone. Threads another writer moved are re-placed from the file when the
source buffer matches the saved file (otherwise see
|sidecar-comments-tracking|), and your unsaved moves of the other threads are
kept.

CONFIGURATION                                   *sidecar-comments-config*

Default configuration:
>
    require('custom.sidecar_comments').setup({
      cmd = 'sidecar',                 -- CLI executable
      sidecar_ext = '.comments',       -- Suffix added to source files
      placeholder = 'comment',         -- Body of new threads and replies
      author_name = nil,               -- Optional --author-name for your messages
      highlight_group = 'CommentLineNr', -- Line number of commented lines
      range_highlight_group = 'SidecarCommentRange', -- Commented text
      priority = 10,                   -- Extmark priority
    })
<
