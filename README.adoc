= Config

Herein lies my configuration files 📜

== Layout

* `home/` contains files that should be symlinked into `~/` (including selected nested app configs like `home/.cursor/cli-config.json` → `~/.cursor/cli-config.json`, `home/.pi/agent/settings.json` → `~/.pi/agent/settings.json`, `home/.pi/agent/packages/pi-guard` → `~/.pi/agent/packages/pi-guard`, and `home/.pi/agent/packages/pi-guard-subagents` → `~/.pi/agent/packages/pi-guard-subagents`)
* `xdg/` contains application configs that should be symlinked into `~/.config/`
* `tmux_and_worktrees/` contains my tmux + git worktree development workflow (tooling built specifically for parallel agentic workflows)

== Setup

Run `./setup.sh` from this repository to install the full config.

It will:

* symlink each entry in `home/` into `~/`
* symlink each entry in `xdg/` into `~/.config/`
* run `./tmux_and_worktrees/setup.sh` to install the tmux/worktree helpers
* reload tmux config automatically when a tmux server is already running

If you only want the home + XDG symlinks, run `./setup_symlinks.sh` directly. For shell changes, open a new shell or run `source ~/.zshrc`.

== Team dev + Pi setup (macOS)

`setup.sh` remains the personal, full-dotfiles setup. Teammates who only need
Pi and the non-writing tmux/worktree commands must run:

[source,bash]
----
./setup-dev-pi.sh
----

This macOS-only installer has an explicit, limited surface: it installs the
current global Pi configuration (packages, extensions, skills, settings, usage,
and guard profile), the `dev` CLI (with `dnew`, `dopen`, `dtree`, `dclose`,
`dkill`, and `dmerge` compatibility wrappers), and the tmux status helper. It does not install or link Cursor, Git, Ghostty,
Neovim, OpenCode, or shell dotfiles. `wopen`, `wnew`, and `wclose` are excluded.

Before changing files it requires existing `pi`, `tmux`, `git`, `python3`,
`node`/`npm` (Node 22.19+), `nvim`, and `lazygit`. Missing tools cause a
nonzero exit before modification, with current installation links or commands.
Pi itself is intentionally not installed by the script.

The local Pi packages have dependencies that are not committed. A fresh clone
will fail the dependency preflight without making changes. After reviewing the
packages, bootstrap those dependencies explicitly:

[source,bash]
----
./setup-dev-pi.sh --bootstrap-pi-deps
----

That command runs `npm ci` in each bundled Pi package and downloads Playwright
Chromium for `pi-webfetch`; it is never implicit. Use `--dry-run` to print the
planned changes, `--status` to inspect current managed links/wrappers, and
`--uninstall` to remove unchanged installer-owned artifacts.

When a selected target already exists, normal setup prompts before moving it to
an adjacent `<target>.bak` backup. `--non-interactive` fails on every such
conflict rather than silently skipping or replacing a file. Existing `.bak`
files are never overwritten. Uninstall restores an adjacent backup only after
it verifies that the replacement is still installer-owned and unchanged;
otherwise it preserves the user file and reports the conflict. The installer
never overwrites `~/bin/pi` and never follows a symlinked `~/.zshrc` or
`~/.tmux.conf` to edit its target.

The installer adds only uniquely marked blocks to a regular `~/.zshrc` (PATH,
`dev home`, and its `dhome` compatibility wrapper) and regular `~/.tmux.conf` (workflow include). It does not reload
an existing tmux server; reload deliberately after reviewing the changes:
`tmux source-file ~/.tmux.conf`.

Pi resources installed here are global and therefore trusted by Pi for all
projects. The included profile, skills, browser tool, and usage tooling reflect
the current repository configuration; review changes under `home/.pi/` as
privileged executable configuration. `dtree` also retains its existing fallback
initializer, which may link `.env`/Terraform files and run `npm ci` when it
creates a worktree.

== Team dev + Pi setup (Windows)

For native Windows, run the PowerShell installer from a PowerShell prompt:

[source,powershell]
----
.\setup-dev-pi.ps1
----

It installs the same explicitly listed global Pi resources (settings, models,
skills, usage, guard configuration, packages, and extensions), with the same
conflict backup, `-DryRun`, `-NonInteractive`, `-Status`, `-Uninstall`, and
explicit `-BootstrapPiDeps` behavior. It requires Git, Pi, Node/npm 22.19+,
and permission to create symbolic links. Enable Windows Developer Mode or run
PowerShell elevated if its symbolic-link preflight fails.

The Windows installer deliberately does *not* install `dev`, the legacy `d*`
wrappers, tmux configuration, or zsh integration: those are Bash/tmux-specific
and remain supported only by the macOS installer. If your execution policy
blocks local scripts, run it explicitly with:
`powershell -ExecutionPolicy Bypass -File .\setup-dev-pi.ps1`.
