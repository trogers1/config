= Shared agent resources

One source for the skills, prompt snippets, and subagents used by Pi, Claude,
and OpenCode. Edit files here; never edit the generated copies.

[cols="1,2,2"]
|===
| Source | Installed as | Used by

| `skills/<name>/`
| `~/.agents/skills/<name>` and, via generated relative links, `~/.claude/skills/<name>`
| Pi and OpenCode (`~/.agents/skills`), Claude (`~/.claude/skills`)

| `snippets/<id>.md`
| `~/.agents/snippets/<id>.md`
| Pi snippet menu (`alt+s`), Claude `/<id>` wrappers and `+<id>` markers

| `AGENTS.md`
| `~/.claude/CLAUDE.md` and `~/.pi/agent/AGENTS.md` (`setup-personal.sh` only)
| Claude and Pi global instructions

| `agents/<name>.md`
| `~/.claude/agents/<name>.md` and the bundled `pi-guard-subagents` agents
| Claude subagents, Pi guarded subagents
|===

`setup.sh` links these sources (except `AGENTS.md`) plus
`home/.claude/{skills,agents,hooks}`, and adds the hooks registered in
`home/.claude/settings.json` (`+marker` snippets, worktree routing) to an
existing `~/.claude/settings.json` without touching its other keys.
`setup-personal.sh` instead links `home/.claude/settings.json` whole, and
shared setup then leaves it alone.

== Global instructions

`AGENTS.md` holds Taylor's preferences that apply to every task in every
repo, and both agents load it in every session. Being personal, it is linked
only by `setup-personal.sh`. Keep it short: task-specific guidance
belongs in a skill or snippet, which the file points to rather than repeats.

== Generated config

`scripts/generate-agent-config.mjs` renders owned entries under
`home/.claude/skills`, `home/.claude/agents`, and
`home/.pi/agent/packages/pi-guard-subagents/agents`, not the entire roots.
External siblings (including `home/.claude/skills/synced`) are ignored by
checks and preserved by writes. Rerun it after changing a skill, snippet,
or agent; `setup.sh` and `tests/setup.test.sh` refuse stale output.
The tracked `scripts/generated-agent-config-ownership.json` is generated from
the expected output entries; do not maintain a separate list of resource names.
Checks and writes consider both that previous ownership and current sources,
so removing a source still detects and cleans its previously generated entry.
Commit the updated manifest alongside generated outputs. Its repository-relative
paths always use `/`, including when generated or checked on native Windows.
External siblings are never adopted merely because they exist. `--skill <name>` restricts either
operation to selected shared skill links and preserves unrelated ownership.

[source,bash]
----
node scripts/generate-agent-config.mjs          # write
node scripts/generate-agent-config.mjs --check  # verify
----

== Skills

Skills use the frontmatter both agents understand. Add
`disable-model-invocation: true` to make a skill manual-only (`/name` in
Claude, `/skill:name` in Pi). Reference bundled scripts through
`~/.agents/skills/<name>/...`, which resolves for every agent.

MR review loop: `export-mr-comments` / `address-comments` / `flow-review` →
`discuss-mr-comments` (interactive, one thread at a time; local approval only) →
`post-mr-replies` (preview and separately approve publishing).
`export-mr-comments` creates a snapshot; `address-comments` adds local Robot
resolution notes and reviewer-facing `Reply — DRAFT` blocks by default;
`flow-review` drafts new findings as `Thread — DRAFT` blocks. Drafts are never
approval, and Robot resolution is not remote thread resolution. Refresh live
context into a scratch file when `comments.md` already exists so local work
and approvals survive.

== Snippets

A snippet's file name is its short id, used everywhere:

* Claude: start a message with up to six wrappers, `/code /noassume fix the parser`
  (autocompleted), or put `+code` anywhere in the message. An unknown `+word`
  shows a warning listing the available ids.
* Pi: toggle snippets in the `alt+s` / `ctrl+shift+s` menu.

Frontmatter: `name` (Pi menu label), `description`, `placement`
(`prepend`/`append`), and `order`. A snippet id must not match a skill name, and neither should match a
Claude built-in command (for example `/review` and `/verify` are taken).

== Agents

Agent prompts are shared; the frontmatter is neutral and mapped per agent:

[cols="1,2,2"]
|===
| Field | Pi | Claude

| `tier: default`
| `openai/gpt-6.1-sol`
| `opus`

| `tier: fast`
| `openai/gpt-5.6-terra`
| `haiku`

| `tools` (Pi names)
| unchanged
| `read`→`Read`, `grep`→`Grep`, `find`/`ls`→`Glob`, `bash`→`Bash`; omitted means all tools

| `profile`
| pi-guard profile
| ignored (Claude has no equivalent until agent-guard)
|===

The model and tool tables live at the top of the generator.
